# POC: Nova components on Expo Exact

Date: 2026-11-11. Exact checkout: `expo/exact` at `ec183f2a` (pre-alpha, pre-1.0).
Machine: Apple Silicon, macOS 26.6.2, Xcode 26.6.

## Question

Can Expo Exact (Contract language + per-platform runtimes) serve as the base of
the next Nova architecture (documentation/data driven, headless logic, contracts,
no Web Component layer)? Decisive sub-question: can its output live inside the
React, Angular, Vue and Blazor applications that consume Nova today?

## What was built

| Piece | Where | What |
|---|---|---|
| Nova component package | `packages/nova-native/` (`@nova-design-system/native`) | `NvButton` (emphasis high/medium, danger, sizes md/sm, disabled, loading, fluid) and `NvFieldtext` (label, required, description, error description, readonly, disabled), in Contract |
| Nova theme | `app.tamber`, generated by `tools/resolve-tokens.ts` | 58 Nova colour tokens from `packages/base/dist/css/spark.css`, light and dark as `light-dark()`, Nova token names kept (`components-button-high-background`), focus tint = `color-focus-brand` |
| Demo app | `app.contract` | A sign-up form made only of Nova components |
| Portable tests | `app.test.contract` | 5 behaviour tests (errors, submit, reset, read-only) |
| Embedding check | `embed/` | A React 19 page that mounts the Exact web build directly, or in an iframe, measured in headless Chromium |

Run it (after `bun ../exact/scripts/exact.mjs setup` and `bun install` here):
`bun exact.mjs test web`, `bun exact.mjs linux && bun exact.mjs test linux`,
`bun exact.mjs web` to look at it, and `cd embed && bun install && bun run check` for the
embedding check. Regenerate the theme with
`FORMAT=tamber bun tools/resolve-tokens.ts ../nova-design-system/packages/base/dist/css/spark.css --components-button-high --components-button-medium --components-button-destructive-high --components-form-field --components-form-text --color-focus-brand > app.tamber`.

## Results

| Check | Result |
|---|---|
| Nova components as a reusable package | Works. A package exports `.contract` files through `package.json` `exports` (`contract` condition); the app imports `use NvButton, NvFieldtext from "@nova-design-system/native"` |
| Nova tokens, light and dark | Works with our generator (58 tokens, `tamber check` clean, correct colours in both schemes, see `shots/web-*.png`) |
| Tamber's own CSS import on `spark.css` | Partial: 1,619 tokens imported with Nova's alias chain kept (`components-button-high-background = color-interaction-container-branded-high-background`), lengths included; but the 689 dark overrides under `.dark:root` are refused (Tamber wants an app axis), so dark mode needs our generator or an axis mapping |
| Compiler feedback | Excellent: precise, actionable refusals with the rule id and the web's spelling (`fit-content` not a valid width, `class=` chooses between two styles) |
| Tests on the web host | 5/5 pass, about 10 s including the build (`shots/web-light.png`, `shots/web-dark.png`) |
| macOS host (AppKit) | Blocked on this machine: Exact's Swift uses a macOS 27 SDK API (`quinaryLabel`), so it needs Xcode 27.1 (we have 26.6). Not an Exact bug, an install gap |
| iOS host (UIKit) | Blocked for the same reason (`exact setup --check`: iOS SDK 26.5, needs 27.1) |
| Painted Rust host (headless, the Linux host's painter run on macOS) | Built in about 1.5 min; the same `app.test.contract` passes 5/5 with no change to the components (`shots/painted-light.png`). It caught one difference the web host let through: typing into a `readonly` field is refused there ("view 22 is readonly") and silently accepted on the web, so the test was rewritten |
| Exact inside a React page, iframe | Works: the Nova form runs and submits inside the iframe; the host page is untouched. But it is a page in a page: no shared styles, focus, routing or props |
| Exact inside a React page, direct mount | Renders only when the host URL matches an Exact route (`/`); at `/host` it mounts an empty root. Exact's global CSS changed the host's `h2` from 28px Georgia to 16px system-ui and its `body` font; `button, input, textarea { all: unset }` would hit every host control styled by element selector (Tailwind preflight, Blazor CSS). One instance per page (`#exact-root` is hard-coded), and Exact drives `history.pushState` / `replaceState` |

## Friction found while porting

1. **Variants.** `class=` names one style or chooses between two; `:hover` / `:active`
   rows must be literals. Nova's button has 4 emphases x danger x 4 sizes: each painted
   variant became its own view branch with the geometry repeated (3 branches for 3 of the
   variants in this POC).
2. **Props have no defaults.** Every use passes every prop
   (`NvButton(label=…, emphasis=…, size=…, danger=false, disabled=false, loading=false, fluid=false, …)`).
   Nova's API relies on defaults (`size='md'`, `emphasis='high'`, booleans `false`).
3. **One slot per component.** Named slots are refused by design. Nova uses many
   (`leading-icon`, `trailing-icon`, `label`, `description`, `error-description`, …); they
   become props or separate components.
4. **CSS defaults are CSS's.** A bare node is `content-box`; Nova assumes Tailwind's
   `border-box`, so buttons first rendered 56px tall instead of 40px until
   `box-sizing="border-box"` was written on each.
5. **The platform owns what is unsaid.** Font (TT Norms Pro was not declared, so the
   system font shows), focus ring (fixed by `AccentColor` in the theme), native controls on
   Apple hosts. This is Exact's philosophy ("write the web, ship the platform"), the
   opposite of a branded design system's pixel parity.
6. **Toolchain.** Rust 1.97, a pinned nightly, Bun 1.4.2, Hermes bundles, Playwright
   Chromium, and Xcode 27.1 for Apple. First setup (`exact setup`) took about 5 minutes here on a fast connection, plus the
   rustup and Bun installs; the first native compile adds minutes per host. None of it
   fits today's npm + dotnet pipeline.

## Assessment

Exact is an **application runtime**, not a component library generator. Its web output
owns the document (root id, global reset, routing). That blocks the main Nova use case:
dropping components into existing React, Angular, Vue and Blazor apps. The iframe works
but gives micro-frontends, not a design system.

Where it would fit: a **new** app that Elia wants on web plus native desktop and mobile,
written entirely in Exact, with Nova as a Contract package and a generated Tamber theme.
This POC shows that path is realistic once Xcode 27.1 is installed.

What Nova should take from it for its own architecture, whatever the runtime:

- A **typed contract per component**: props, state, actions, events, one slot, in a small
  declarative language that a compiler checks and refuses with actionable messages.
- **Portable behaviour tests** (`*.test.contract`): one script of operations (`tap`, `type`,
  `expect text`, `expect tree`) run against every implementation (React, Angular, Vue,
  Blazor) instead of one e2e suite per framework.
- **Tokens kept by name in a checked theme file** with light/dark pairs and contrast checks
  (`tamber check`), generated from the Figma pipeline.
- **Agent-first tooling**: JSON diagnostics with stable ids, a driver with a controllable
  clock, screenshots per host.

## Recommendation

- Do not adopt Exact as Nova's foundation now: pre-alpha with daily breaking changes,
  private design records, no embedding story for existing apps.
- Keep watching it (it moves fast; re-check the embedding story in a few months).
- Reuse its ideas in Nova's own contract format and test runner.
- If Elia has a concrete native desktop or mobile app need, rerun this POC on macOS and
  iOS after installing Xcode 27.1: the same `app.contract` and tests should run there
  unchanged.
